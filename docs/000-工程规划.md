## 1. 背景与定位

### 1.1 一句话定位

**以 AAR 形式发布的、Android 版 `python` / `pip` 命令行**——基于 **PEP 738**（CPython 3.13+
官方 Android 支持）交叉编译的 `libpython_cli.so`（arm64-v8a，exec 型 PIE），扩展模块**全部
静态链入**，assets 随包纯 Python stdlib + **pip 树** + ensurepip + CA bundle。终端里由
node-pty 经 `forkpty` + `execve` 启动，与 `aosp-uv-cli` 组合成完整 python 工具链。

### 1.2 为什么需要它

- 原生 Android 没有 python（`/system/bin` 只有 mksh 与 toybox）；
- 终端（PTY）需要**独立进程**的解释器，而不是进程内嵌入；
- CPython 3.13+ 官方支持 Android 交叉编译（PEP 738），不再是社区补丁形态。

### 1.3 边界（在范围 / 不在范围）

| 在范围内 | 不在范围内 |
|---|---|
| `libpython_cli.so` 的 PEP 738 交叉编译、exec 门禁、AAR 打包、发布 | 任何嵌入 API / 进程内 libpython（出现真实需求另立 `aosp-python-runtime` 线） |
| stdlib/**pip**/ensurepip/CA 的随包与 sha256 出处记录（`pip` 命令经壳脚本直出，见 D6） | pip 装 **sdist** 包 / 含 C 扩展的 wheel（设备无编译器 + 静态解释器不能加载新 .so，能力边界） |
| 版本事实源 `python-cli.lock.json`（独立 semver） | tkinter/curses/readline 类 UI 模块（首版不编） |
| 环境变量契约与回程探针定义（§7） | python 环境管理（venv 组合由消费方/环境引导层实现）；uv 本体（属 aosp-uv-cli） |

## 2. 版本规则

- 制品版本 = CPython 上游版本，**独立 semver**，与 node 系无配对（无 NODE_MODULE_VERSION 约束）；
- 升级 = lock 增项 + CI 重新构建（镜像 pty 的 release 纪律）；
- 当前 draft 计划版本 `3.14.10`（2026-11-02 钉选）：M1 开工时以 CI 实际可构建的最新稳定版钉选并回写。

## 3. 总体架构与关键决策

```
┌─ 消费方 App 进程 ────────────────────────────────────────────────┐
│  环境引导层（bridge 载荷或 Kotlin）                                │
│   - assets/python-bridge-tools/ 幂等物化 → filesDir               │
│   - 注入 PYTHONHOME/PYTHONPATH/SSL_CERT_FILE/PATH/HOME/TMPDIR     │
│        │ pty.spawn(<nativeLibraryDir>/libpython_cli.so, …)        │
│        ▼                                                          │
│  python 子进程（exec 型，独立生命周期；forkpty → setsid → TIOCSCTTY）│
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 关键决策记录（不可回归项）

| # | 决策 | 理由 | 反面（禁止） |
|---|---|---|---|
| **D1** | **扩展模块全静态**（`Modules/Setup.local` `*static*`） | targetSdk≥29 SELinux 禁止从 filesDir `dlopen`；动态扩展 .so 落地即废 | 动态扩展 + 自定义 importer（复杂一个量级，留给未来 `-runtime` 线） |
| **D2** | **exec 打包 `useLegacyPackaging=true`** | exec 要求物理落盘 nativeLibraryDir，不落盘则 `execve` ENOENT | `useLegacyPackaging=false`（pty dlopen 库的口径，与本仓相反） |
| **D3** | **版本 = CPython 上游版本，独立 semver** | 与 node 系无 ABI 约束；uv/pnpm/git 同口径 | 与 runtime 配对（无必要） |
| **D4** | **stdlib 走 assets→filesDir 物化** | 纯数据无需 exec 位；复用 bridge payload 物化 + marker 纪律 | stdlib 直接放 jniLibs/ZIP 内 mmap（解释器需要真实路径） |
| **D5** | **PEP 738 官方路径**（不做源码补丁） | 官方支持 Android 交叉编译；配置经 configure 参数注入 | 第三方 fork / 源码补丁（违反 fetch 不改源纪律） |
| **D6** | **pip 树直接随包 + 壳脚本入口**：官方 pip wheel 解包进 `Lib/site-packages/`（钉版 + sha256），`libpip.so`/`libpip3.so` 壳脚本 → `libpython_cli.so -m pip "$@"` | 首启即有 `pip` 命令、离线可用、零引导步骤；pip 为纯 py 不需 exec 位（壳脚本落在 nativeLibraryDir 合规） | 只靠 ensurepip 引导（首启多一步，且 `pip` 非直接命令可用） |

## 4. 构建设计（M1 核心）

### 4.1 工具链与源钉选

| 项 | 取值 | 说明 |
|---|---|---|
| CPython 源 | `python.org/ftp/python/<ver>/Python-<ver>.tgz`，SHA-256 校验 | fetch 不改源；版本钉选见 §2 |
| NDK | **27.3.13750724**（CPython 3.14.10 官方 `Android/android-env.sh` 硬编码钉版；CI 首跑核对 2026-11-02，原 r28c 设想作废——改上游脚本违反 C1） | 一台 runner 一条 NDK 线；lock.builtFrom.ndk 记录 |
| host 构建解释器 | **必需**：交叉编译需同版本 host python（`--with-build-python`）⬜ | runner 上用官方安装包/源码构建 host python；版本必须与目标一致 |
| OpenSSL | vendored 源码钉版 + `./Configure android-arm64 no-shared` | `_ssl`/`_hashlib` 静态链入；版本写入 lock.builtFrom.deps |
| sqlite3 | 官方 amalgamation（sqlite3.c）vendored | `_sqlite3` 静态链入；版本同上 |
| **pip** | **官方 wheel（files.pythonhosted.org）钉版 + sha256，解包进 `Lib/site-packages/`**（D6） | 纯 py；版本随 lock.builtFrom.pip 记录；wheel 内 bin 脚本不使用（入口为壳脚本） |
| libffi | ⬜ 开放问题：`_ctypes` 依赖 libffi 的 Android 交叉编译较繁琐 | 首版将 `_ctypes` 列为第二批（pip/uv 主链路不依赖 ctypes） |

### 4.2 交叉编译流程（build-python-cli-android.sh，M1 实现）

```
① env：TOOLCHAIN=<ndk>/toolchains/llvm/prebuilt/<host>；TARGET=aarch64-linux-android<api>
② host python 校验：<build-python> --version 必须等于目标版本（不等即失败）
③ configure：
   CC=clang --host=aarch64-linux-android
   --with-build-python=<host python>
   保留 ensurepip                                      # 选项名以实际 configure 为准 ⬜
   LDFLAGS="-Wl,-z,max-page-size=16384"
   静态扩展：Modules/Setup.local 写 *static* 段（_ssl/_hashlib/zlib/_sqlite3/…）
   禁用：tkinter/_tkinter、curses、readline、dbm、_test* 全家
④ make -j$(nproc) → python 可执行（PIE）
⑤ llvm-strip --strip-unneeded → libpython_cli.so
⑥ stdlib 收集：Lib/ 剔除 test/ idlelib/ tkinter/ __pycache__/ *.pyc → stdlib-assets/
⑦ pip 树解包（site-packages）+ ensurepip wheels 提取 + cacert.pem（cURL 来源，SHA-256 钉选）
⑧ BUILD-METADATA.txt / FETCH-METADATA.json（镜像 pty 归档形态）
```

要点与风险：

- **host build interpreter 是官方交叉编译前置**（PEP 738），runner 上多一步同版本构建；
- **静态扩展的 Setup.local 行**是本工程最大新工——每行一个模块 + 链接参数；`_ssl` 的
  OpenSSL include/lib 路径注入；⬜ 以 3.14 实际 Setup 语法为准在 M1 首轮试编；
- **体积预估**：⬜ 二进制 10–25MB（静态 OpenSSL/sqlite 后偏大）+ stdlib ≈10MB（未压），
  首产实测回填 lock。

### 4.3 官方辅助路径（优先采用）

CPython 源码树自带 Android 构建文档与辅助脚本（PEP 738 引入，`Android/` 目录），涵盖
host build python、configure、testbed（模拟器跑测试）——**build 脚本优先包装官方辅助脚本**，
避免自研一遍交叉编译流程；包装失败再退回手写 configure。⬜ M1 以 3.14 树实际内容为准核对。

## 5. 制品形态与打包投放（AAR）

```
python-cli-<ver>.aar
├── jni/arm64-v8a/libpython_cli.so           # exec 型 PIE（ET_DYN + PT_INTERP=/system/bin/linker64，16KB 对齐）
├── jni/arm64-v8a/libpip.so                  # 壳脚本（sh）：exec libpython_cli.so -m pip "$@"（D6）
├── jni/arm64-v8a/libpip3.so                 # 壳脚本（sh）：同上，pip3 别名
└── assets/python-bridge-tools/
    ├── Lib/…                                # 纯 py stdlib（已剔除 test 等）
    │   └── site-packages/pip/…              # pip 纯 py 树（官方 wheel 解包，钉版+sha256，D6）
    ├── ensurepip/…                          # pip wheels（修复/兜底路径保留）
    ├── cacert.pem                           # CA bundle
    └── manifest.json                        # 文件清单 + 逐文件 sha256 + 总 sha256
```

- 打包：**`useLegacyPackaging=true`**（D2）；模块只作 AAR 容器，无任何 Kotlin/Java 源；
- provision 扩展（M1）：`--assets <dir>` 把 stdlib-assets 投放进 assets 并生成/校验
  manifest.json（万级文件不逐条比对 git，只用清单哈希）；
- jniLibs 纪律：`libpython_cli.so` + **壳脚本白名单**（`libpip.so`/`libpip3.so`，
  provision `--check` 放行清单扩展），仍禁入 `libnode.so`；
- META-INF/python-cli.properties 增加 `stdlib.sha256` / `pip.version` / `openssl.version` /
  `sqlite.version`。

## 6. exec 型门禁 profile

| 门禁 | 判据 | 与 pty（dlopen 库）门禁的差异 |
|---|---|---|
| ELF 形态 | `ET_DYN`（PIE） | 同 |
| 解释器 | **PT_INTERP 恰 1 个且 = `/system/bin/linker64`** | **相反**（pty 要求 PT_INTERP=0） |
| 依赖 | **DT_NEEDED 白名单**（系统库 + lock 登记） | pty 是"必须含 libnode.so" |
| NAPI | 无门禁 | pty 有"napi_* 未定义引用"门禁 |
| 页对齐 | 16KB（`-Wl,-z,max-page-size=16384`） | 同 |
| 出处 | sha256 / size / 源版本 / NDK / flags | 同 |

- **已实现（M0）**：provision 退出码 0/2/1，draft 只记录不比对；
- **M1 新增**：① `--assets` 投放 + manifest 生成/校验；② **静态性检查**——stdlib-assets
  内不得出现 `.so`（防动态扩展漏网）；③ 产物内嵌检查（可选，⬜ 手段 M1 定）；
  ④ **jniLibs 兄弟文件白名单扩展**——放行 pip 壳脚本（内容为 sh 的 `libpip*.so`），
  其余非白名单 `.so` 仍拒绝。

## 7. 运行期契约（消费方 / 环境引导层）

| 环境变量 | 值 | 说明 |
|---|---|---|
| `PYTHONHOME` | `<filesDir>/python-bridge-tools` | 物化后的 stdlib 根（含 `Lib/`） |
| `PYTHONPATH` | 默认空（pip 树在标准布局 `Lib/site-packages/`，由 site 自动导入） | 用户包装目录可追加 |
| `SSL_CERT_FILE` | `<filesDir>/python-bridge-tools/cacert.pem` | Android 无系统证书目录 |
| `PATH` | `<nativeLibraryDir>:$HOME/bin:/system/bin` | pip 装 CLI 脚本落在 filesDir 不可直接 exec（见下） |
| `HOME` / `TMPDIR` | filesDir 子目录 | pip 缓存/venv 目录 |

- 物化机制：复用 bridge payload 纪律（marker 幂等、失败结构化上报、版本升级时清残留）；
- **已知限制（消费方文档必须写明）**：pip 安装的 CLI 脚本在 filesDir 不可直接 exec
  （SELinux C1），须以 `python -m <mod>` 或 pip 内部机制调用；sdist 不可安装。
- **venv/uv 环境边界（2026-11-05 追记，来源 `docs/20261105-cli-实测问题-修复设计.md` §2.2/§4.2/§4.3；不改变既有契约）**：
  `python -m venv` 的 `pyvenv.cfg home` 写为**解释器软链所在目录**（无 stdlib）→ venv 解释器
  找不到 stdlib；uv 建环境还写死**符号解析后**的 realpath home（uv 自身缺陷）。**裸执行不保证**，
  自愈由消费方环境引导层（dsh-desktop-android）负责：构造自洽 prefix（`pyvenv.cfg home=自身` +
  `bin/python→libpython_cli.so` 软链 + `lib/python3.14→stdlib`）+ 覆写 `home`；覆写 home 指向
  含 stdlib 的 prefix 后 `.venv/bin/python -m ensurepip` 可装 pip。sdist 不可设备编译（能力边界，
  消费方 README 按修复设计 §4.3 口径披露）。

### 10.1 发布模式（GitHub Release 先行、Maven Central 随后）

沿用 aosp-node-pty 的两段式发布：

1. **先行：GitHub Release（M1-T7，tag `v<pyver>` 推送触发）**——归档
   `python-cli-v<ver>-android-arm64-v8a.tar.gz`（libpython_cli.so + libpip 壳脚本 +

2. **随后：Maven Central（M3）**——执行口径按工作区

   `publish.gradle.kts` 已内置该管线（RELEASE=false 默认，POM SCM url 补丁指向本仓）。

  约束、无配对顺序要求）；assets（stdlib/ensurepip/CA）随 AAR 一同发布，manifest 校验

## 12. 质量门禁汇总

| 门禁 | 判据 | 在哪强制 |
|---|---|---|
| ELF 形态 | ET_DYN（PIE）、PT_INTERP=系统 linker64、AArch64、16KB 对齐 | provision + CI |
| 依赖白名单 | DT_NEEDED ⊆ 系统库 + lock 登记库 | provision |
| 静态扩展 | 产物不携带独立扩展 .so（stdlib 资产内无 .so） | provision/assets 检查（M1） |
| 壳脚本白名单 | jniLibs 仅 libpython_cli.so + libpip*.so | provision（M1） |
| 不入库 | jniLibs/**/*.so 与 assets 树被忽略 | .gitignore + review |
| 可复现 | 干净 runner 单条 workflow 重出同口径产物 | CI（M1） |
| 许可 | CPython PSF-2.0 + pip(MIT) + OpenSSL + wheel 许可 | THIRD-PARTY-NOTICES.md |
| 发布卫生 | RELEASE=false 默认；Token/GPG 不入库 | gradle.properties / publish |
