## 3. 设计

### 3.1 五源钉选（FR-001-001/002/003/004）

`python-cli.lock.json` `releases[i].builtFrom` 新增结构化 `deps` 表（记录面，工具读版本+sha256）：

```jsonc
"deps": {
  "cpython":   { "version": "3.14.10", "url": "https://www.python.org/ftp/python/3.14.10/Python-3.14.10.tgz", "sha256": "" },
  "openssl":   { "version": "3.5.x",  "url": "https://www.openssl.org/source/openssl-<v>.tar.gz", "sha256": "" },
  "sqlite":    { "version": "3.50.x", "url": "https://sqlite.org/2025/sqlite-amalgamation-<v>.zip", "sha256": "" },
  "pip":       { "version": "25.x",   "url": "https://files.pythonhosted.org/.../pip-<v>-py3-none-any.whl", "sha256": "" },
  "cacert":    { "version": "2025.xx.xx", "url": "https://curl.se/ca/cacert.pem", "sha256": "" }
}
```

- **sha256 空串 = 未钉选**：fetch 拒绝执行（exit 1，提示先钉选），**不**做「下载后回填」
  ——避免把「先拿到什么」冒充「钉选了什么」（C2/C6）；钉选值由维护者以官方公布哈希回写。
- 版本升级 = deps 表改值（CPython 大版本另起 `releases[]` 新条目，规划 §8）。
- fetch 可重入：目标文件存在且 sha256 一致 ⇒ 跳过下载（FR-001-002）；哈希不一致 ⇒ exit 1
  （缓存污染信号，不自动重下）。

### 3.2 构建脚本八步（FR-001-010…014/020…023/034，规划 §4.2 ①–⑧）

`scripts/build-python-cli-android.sh --python <ver> --api 24 --src <dir> --ndk <dir> --out <dir>
[--host-python <path>] [--jobs N] [--dry-run] [--extension-mode static-first]`：

| 步 | 内容 | 关键纪律 |
|---|---|---|
| ① env | 解析 NDK toolchain 前缀与 `aarch64-linux-android<api>` clang | NDK 路径不存在 ⇒ exit 1 |
| ② host python 校验 | `<host-python> --version` ≠ 目标版本 ⇒ exit 1（FR-001-010） | 版本串逐段比较（3.14.10 ≠ 3.14.10a1） |
| ③ configure | `CC=clang --host=aarch64-linux-android --with-build-python=<hp>` + `LDFLAGS=-Wl,-z,max-page-size=16384`；写 `Modules/Setup.local` `*static*` 段（_ssl/_hashlib/zlib/_sqlite3 + vendored 路径）；`--disable-` / 剔除 tkinter/curses/readline/dbm/_test* | 选项名以 3.14 树实际 configure 为准（R1 ⬜）；`--dry-run` 打印将执行的命令 |
| ④ make | `make -j$(nproc)` → `python` 可执行（PIE） | 失败 ⇒ exit 2 |
| ⑤ strip | `llvm-strip --strip-unneeded` → `$OUT/libpython_cli.so`（FR-001-014） | 输出名取自 lock `active.name` |
| ⑥ stdlib 收集 | `Lib/` → `$OUT/stdlib-assets/Lib/`，剔除 test/idlelib/tkinter/__pycache__/*.pyc（FR-001-020） | 复制后核对剔除项计数 |
| ⑦ pip/ensurepip/CA | pip wheel 解包进 `stdlib-assets/Lib/site-packages/`（FR-001-021）；`libpip.so`/`libpip3.so` sh 壳写入 `$OUT/`（FR-001-022）；ensurepip wheels 拷贝 + `cacert.pem`（FR-001-023） | 壳脚本内容见 §3.3 |
| ⑧ 元数据 | `BUILD-METADATA.txt` + 复制 FETCH-METADATA.json（FR-001-034） | 版本/NDK/flags/UTC 时间 |

- `--extension-mode static-first`：静态段生成后逐模块编译失败 ⇒ **exit 2**（默认，C4）；
  维护者显式传 `--skip-extensions <mod,...>` 才裁剪，且写入 BUILD-METADATA（FR-001-013）。
- `--dry-run`：①②③ 的命令与将写入的 Setup.local 全部打印不执行——本批 Windows host 的
  代码级验证入口（语法/参数/流程可测，不依赖 NDK）。

### 3.3 pip 壳脚本（FR-001-022，D6）

```sh
#!/system/bin/sh
# libpip.so / libpip3.so — generated by build-python-cli-android.sh (do not edit)
exec "$(dirname "$0")/libpython_cli.so" -m pip "$@"
```

- shebang 用 `/system/bin/sh`（Android 无 /bin/sh）；`dirname "$0"` 解析同目录解释器
  （nativeLibraryDir 内自定位，不依赖 PATH）。
- 生成时 `chmod +x`；投放后 provision 白名单校验内容前缀（§3.4）。

### 3.4 provision 扩展（FR-001-030…033/035）

`tools/provision.mjs` 新增/变更（既有接口不变，见 [`../000-scaffold/plan.md`](../000-scaffold/plan.md) §5.1）：

| 参数 | 行为 | 退出码 |
|---|---|---|
| `--assets <dir> --assets-mode stage`（默认） | 静态性检查（树内出现 `.so` ⇒ 拒绝）→ 复制 `<dir>/` → `python-cli/src/main/assets/python-bridge-tools/` → 生成 `manifest.json`（逐文件 sha256 + 文件数 + 总 sha256 + 生成时间） | 0/2/1 |
| `--assets-mode verify`（配合 `--check`） | 按已投放 `manifest.json` 复验：文件集合一致（多/少/漂移逐项报告） | 全过 0，任一差异 2 |
| jniLibs 白名单（变更） | 兄弟 `.so` 允许：`libpython_cli.so`（主件）+ `libpip.so`/`libpip3.so`（**内容须以 `#!/` 开头且含 `-m pip`**，防真二进制伪装）；其余 `.so` 仍拒绝 | 违规 ⇒ 2 |

- manifest.json 形态（镜像 bridge payload 纪律）：`{ tool, version, abi, files: { "<relpath>": "<sha256>" }, fileCount, totalSha256, generatedAt }`；
  `totalSha256` = 对「relpath+sha256」排序串的摘要（树摘要与目录序无关）。
- 幂等：重复 stage 先清空目标目录再投放（版本升级清残留，规划 §7 物化纪律同源）。
- 万级文件性能：流式逐文件哈希（`createHash` 管道），不整树读内存。

### 3.5 lock 字段扩展（FR-001-004）

`releases[i].builtFrom` 由纯字符串演进为**保留既有字符串键 + 新增 `deps` 对象**
（向后兼容：`provision.mjs` 只读 `active`/`releases[].{version,abi,name,size,sha256,status}`/
`matrix.allowedNeeded`，不触碰 `builtFrom`，无解析风险）。draft 期 deps 五项 sha256 全空串。

## 4. 实现策略

1. **顺序**：lock 扩展 → fetch 实现 → 壳脚本/stdlib 收集（build 脚本 §⑥⑦ 可独立本地测）→
   build 脚本①–⑤（CI 执行体 + 本地 dry-run）→ provision 扩展 →（CI 接线归 002）。
2. **本地可测/不可测切分**：本地可测 = fetch（真实网络下载五源）+ ⑥⑦（用 host python 3.11 的
   `Lib/` 作 stdlib 输入替身）+ provision 全链（合成 fixtures）+ build `--dry-run`；
   不可测 = ①–⑤ 真实编译（CI ⬜）。
3. **错误处理**：所有外部命令失败 ⇒ 定位到步号报错；门禁/校验类失败 exit 2、用法/IO exit 1
   （FR-001-035 与 FR-000-032 同口径）。
